AMBIGUITIES
1. Row-id format: TASK's `<row id>[<variant>]` was read as "variant letter appended when present" (M50a, C1), not literal brackets.
2. M46 (and the FORK+INIT basis of M50c, M53a-c): FORK+INIT is also an ordinary DECISION 25 creation proof. Chosen reading: A2 still applies to a never-live lifetime ("release FORK and any genuine INIT normally, then UNTRACED"), so M46 emits UNTRACED; alternative reading treats D as an ordinarily created generation and emits FORK -> INIT -> EXIT -> F12 without UNTRACED. For M50c/M53, either reading yields unknown_evidence because the delivered INIT contradicts EXIT's stored INIT state.
3. M49/M50/M52a/M53/M57b-c/M58/M60/M61/M63e: the contract does not fix whether FAULT(unknown_evidence) is reported on EXIT arrival, at terminal reconciliation, or at eligible-batch validation for W=13; all readings give the identical output (single VOID20, no prefix) because W=0 until the last boundary and d=20 throughout.
4. M52b: BOUNDARY inputs carry no counter vector; ROWS says "every unstated observation [is] C0". Chosen: the S(13) boundaries carry no counter observation, so only the CHECK(Cx) VOID appears. If they were read as C0 observations after Cx, a further counter_unknown (reset) or counter_change VOID20 per observation could be argued.
5. M52c: chosen VOID (EXIT (30,2) with no FORK is definitively missing evidence once L passes 13) over "hold" (D's FORK awaiting its own EXIT). Fault dominates hold because a lost dependency in the eligible batch causes VOID.
6. M55: whether the uncertified FORK_D10 counts in the "output sequence"; chosen yes (base §3 "remains observable"; ROWS "including any prefix before a fault").
7. C4b, C24: whether a contradictory certificate makes the "omission inventory" invalid (withhold note) or only the cohort certificate invalid (the single complete pair could yield note 1/6 ms). Chosen: withhold, since the note requires the inventory to be "complete and consistent" and is returned only for limit/unqualified/base failures.
8. C14b: chosen untraced_incomplete (retention removed a pair member) over untraced_invalid (certificate U=2 vs one complete pair); the orphan GAP_OPEN shows the identity exists, so it reads as missing, not contradictory.
9. C14c: whether the two retained complete pairs still give a note without the certificate. Chosen: withhold, because without the finality certificate the pairs may be a known subset ("do not label a known subset as the complete upper bound").
10. Diagnostics: the contract requires returning policy revision/H/K/L/N_qual/qualification identity with every core result and receive_ns-fork_ns only as a labelled diagnostic; listing receive delays for omissions that do not overlap W (e.g. C19c) is optional rather than required.
