# link-closure-allow.txt — new link-time dependencies that are ALREADY
# satisfied everywhere the translation unit is linked.
#
# scripts/check-link-closure.sh fails when a TU references a symbol it did not
# reference at the merge base. Most of the time that is the defect it was
# written for. Sometimes the dependency is deliberate AND harmless, because
# the object that provides it is already a mandatory companion of the TU's
# object in every target that links it. This file is where that case is
# declared — and the declaration is CHECKED, not trusted: for each entry the
# guard reads tests/Makefile and requires every target linking the TU's object
# to link the provider's object too. An entry naming the wrong provider, or a
# provider that some target does not link, FAILS exactly as an undeclared
# symbol does.
#
# That is what keeps this from being the usual escape hatch. You cannot
# silence the guard by editing this file; you can only record which object
# supplies the symbol, and the Makefile has to agree.
#
# Format:  <symbol>  <provider-object-basename>   # justification
# The basename carries NO .o suffix: the guard appends it (it checks the
# Makefile for `$(BUILD)/<basename>.o`), so an entry written as
# `summary_writer.o` is looked up as `summary_writer.o.o` and fails.
# (symbol as `nm` prints it, with the platform's leading underscore or
#  without — both spellings are accepted, so one file works on macOS and
#  Linux.)

# The v9 producer call is now wired in pgwt_read_state_map in src/map_reader.c.
pgwt_summary_note_open_ex  summary_writer   # Every target linking map_reader.o already links summary_writer.o, and has since #379 because the daemon build already called v8's pgwt_summary_note_open (see tests/Makefile); v9 uses the same provider, not a new one. The guard independently re-checks this against tests/Makefile.
