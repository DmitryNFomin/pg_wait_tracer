## 2. The release gate and the nineteen open blockers

`tag-blocker` means an open defect that makes the tag wrong, on any one of:

- **(a)** the product reports a number a user would act on that is wrong, or two
  views of one quantity disagree;
- **(b)** a UX defect on a path a user takes -- a control that does nothing, a
  raw internal token or `null` shown as a value, a view that never recovers from
  an error, a label that contradicts the data;
- **(c)** a documented guarantee is false;
- **(d)** a gate we rely on for (a)-(c) cannot detect its own failure case.

**Not** blockers: our own process tooling and dashboards; test coverage for a
defect that has not shipped; anything whose fix is a documentation change. There
is no materiality threshold -- a wrong number is wrong at any magnitude.

## 5. The machinery

**Three commands.**

| Command | Where | When |
|---|---|---|
| `make check` (`check-fast` for seconds) | this Mac: Node builders, Go bridge, `py_compile`, Playwright UI/chaos against `tests/mock_server.py` | before every push; the pre-push hook enforces a matching stamp |
| `make box-check [OS=…] [PG=…]` | x86 Linux over ssh: build, C units, synthetic data, protocol drift, real-PG capture, live UI smoke | before every PR |
| `make ui-gallery` | this Mac: every UI snapshot cell | before any PR touching `web/` |

`make box-check EPHEMERAL=1` creates a private Hetzner VM from a
`pgwt=gate-snapshot` image, the same machine class as the gate boxes. Use it only
when the persistent boxes are busy, and delete your VM **by id**
(`tests/hetzner-vm.sh delete <id>`), never with a sweep cutoff.

**Access.** The Hetzner token is in the macOS Keychain, service `hcloud`, account
`claude_token`; read it inside a subshell and never print it. `PGWT_BOX` (and
`PGWT_BOX_EL8`, `PGWT_BOX_EL9`) must be exported for the box targets; the lead
sweep reports them as UNKNOWN when they are not set, which is normal for a fresh
shell and not a fault.

**The boxes.** `pgwt-gate` 2.28.45.47, `pgwt-gate-2` 142.132.191.18,
`pgwt-gate-3` 46.225.142.12, all cx33 (`hcloud server list`). The owner keeps
gate-3 and will drop it himself. **They are also the CI runners**, so an agent's
box-check starves CI and stalls merges: check the flock before starting
(`ssh root@<ip> 'fuser -v /tmp/pgwt-box-check.lock'`). A box excluded from
general gating stays available for one thing only -- reproducing the very issue
that excludes it (`CLAUDE.md` line 179) -- so do not treat gate-3 as a general
scratch box. `make check` on the Mac serialises through
`scripts/check-lock.sh`, which makes three concurrent tasks the practical cap.
`PGWT_SKIP_PUSH_GUARD` and `PGWT_SKIP_CHECK_LOCK` are for humans; never set them.

**Evidence binds to a tree, not to a branch.** `scripts/box-check.sh` writes
`commit=<sha> tree-hash=<scripts/tree-hash.sh>` in its log header, and a log is
evidence for a PR head only if that head's `scripts/tree-hash.sh` equals the
logged `tree-hash`. That is how an implementer's box run was reused for a commit
that did not exist when the run happened -- and how the same claim was caught
being false for a second branch. For `make check`, the authority is
`.pgwt-check.stamp`: `scripts/check.sh` removes the stamp when a test fails, so
a stamp that equals `scripts/tree-hash.sh` is the pass signal. Compare the stamp
to the tree hash; do not read a stamp as overriding a visible failure.

**The dispatch path and its one hard limitation.**
`scripts/lead/codex-task.sh <brief-file> <branch>` clones to
`/private/tmp/pgwt-codex/<flattened-branch>`. **A fresh clone always starts the
branch from `origin/master`, never from `origin/<branch>`**: it fetches only
`master` and bases the branch on that. An existing clone that already has the
branch checks it out instead. The brief cannot change the base -- a round that
must continue a branch already published has to prime the clone first, or tell
the agent to fetch and reset to that branch itself inside the clone.
It runs `codex exec --sandbox workspace-write`; codex is a Mac-local install
whose model is pinned in `~/.codex/config.toml` (`gpt-6.1-sol`), with
`-m gpt-6-astra` for the Astra adviser.

**The implementer cannot write under `.git`**, so it cannot commit: a round that
reaches the end exits `BRANCH_UNCHANGED`, which is expected rather than a
failure, and it is filed as open issue **#777** (2026-11-04). Eighteen of the
twenty logged dispatch rounds end that way; the other two died earlier, at a
syntax error I caused by editing this wrapper while they ran.
The wrapper (as of the commit that adds this document) writes the working tree to
`<brief>-salvage.patch` and prints `SALVAGE_PATCH: <path>`. The working pattern
is three-stage:

1. codex writes the code and runs the gates in its clone, then reports;
2. a **landing agent** on this Mac applies the patch to a fresh worktree off
   `origin/master`, checks that `scripts/tree-hash.sh` reproduces the hash in the
   implementer's box log, commits, runs full `make check`, verifies the stamp,
   and pushes -- without opening the PR;
3. a **fresh reviewer** (Opus for `src/` logic, Sonnet otherwise, never the agent
   that wrote the code) verifies the evidence, executes the branch's own negative
   controls itself, and writes the PR body. The lead then opens the PR and arms
   auto-merge in the same turn as a READY verdict.

A `nohup … &` launcher returns immediately, so a harness "completed" notice does
not mean codex finished; check `ps -o pid,etime,command -ax | grep "codex exec --cd"`.

**The lead's own guards.** `scripts/lead/audit-report.sh <draft>` has codex
re-derive every claim in a status report and returns SEND or BLOCK -- no report
reaches the owner unaudited. It is not a formality. On 2026-11-10:

## 6. Traps that cost real time

- **A code read is not a defect report.** Both recent measurement rounds
  overturned a code-read conclusion; one of them turned into #839.
- **Publish measurements, not characterisations.** Most of the wrong claims
  caught in today's audits were a ratio, a scale or a fraction rather than a
  measured number; the rest were absence claims, which need the same treatment
  -- paste the command that would refute them.
- **An adviser's number needs the provenance you demand of your own.** Two wrong
  published numbers today came from an adviser's derivation off a file whose
  other rows contradicted it.
- **Read the whole measurement file before citing it.** The same file produced
  two separate wrong claims because its third row was never read.
- **The issue body is not the decision.** Scope decisions live in the comments
  (`gh api repos/:owner/:repo/issues/N/comments`). #439, #573 and #194 all have
  comments that change or refute their titles.
- **Never edit a shell script while an instance is running.** `sh` reads by byte
  offset, so the running instance resumes into shifted bytes; `sh -n` and the
  selftest both pass while live dispatches die.
- **The local `master` ref and the main checkout are both stale.** Read code with
  `git show origin/master:<path>`, and quote the variable.
- **Cite only the output of a command you just ran.** Three published pastes
  cited line ranges that did not contain the quoted lines.
- **`git stash` is repo-wide**, and a pop in one worktree can apply another
  agent's shelf; use `git worktree add` for absence controls.
- **A squash merge inherits closing keywords** from commit messages, not only the
  PR body, and a negated "does not close #N" still closes #N.
- **`gh pr update-branch` invalidates box evidence**: its merge commit has no run
  of its own. Disarm auto-merge, re-gate, re-arm. PR #841 is in that state now.
