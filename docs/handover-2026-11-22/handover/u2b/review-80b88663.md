## What changed
- In Live mode (`live_edge`), AAS and heatmap responses keep their window totals again. `max_aas`, `max_count` and `total_events` are computed over the buckets that lie wholly before `covered_to`. Buckets past `covered_to` are null in AAS and have no cells in the heatmap. Null cells and `missing_buckets` are no longer injected. This matches tests/mock_server.py and the web fixture.
- `info` is never withheld. On an empty default clip it is labelled `incomplete [not_captured]` and keeps now_ns, from/to, protocol, server_version, num_cpus and the boot, gap and hole lists. Every other route is still withheld on an empty clip.
- The coverage model is cached per file identity: stat of the file and of its `.meta`, including nanosecond mtime and ctime. Only newly committed blocks of a growing current.trace are read. Each request does one refresh and one status-socket read.
- New tests: a whole-response shape check against the mock for complete, live_edge and incomplete; a C cache-vs-fresh test (`test_coverage_trace`, registered); refresh_once; a timing test. There are 2 new mutants, so 10 in total.

3. **Refresh cost (finding 3): fixed.** My measurements, steady state per request in one session, info/aas/time_model/top_events/heatmap ×12, whole-day window:
   - 24 hourly files × 3,600 WATERMARKs: max 10.5 ms, mean 3.3 ms.
   - The same plus 1,008 gaps (incomplete, capture_loss): max 12.6 ms, mean 5.7 ms.
   - 23 archives plus a growing current.trace, with meta advanced before every request: max 10.2 ms.
   - Cold start (spawn plus first info): 45 ms on HEAD, 121 ms on c99a35ce, 11 ms on the base. The base and c99a35ce figures are the first review's -O1 builds.

   Cache-correctness hunt. The oracle was a fresh server process at each state, compared with a long-lived session on coverage, from/to, boots, gaps, holes, db_time_ms, max_aas and code:
   - 232 requests over meta-only growth with a gap, 0 mismatches.
   - 456 requests over byte-level growth with a torn partial block written before the meta commit and the meta committed after, 0 mismatches.
   - Liveness on cached data, L = 3 s:
     - No socket: live_edge.
     - A socket with the wrong nonce: incomplete [unclean_end].
     - A socket with the matching nonce: live_edge.
     - After 4 s with no growth: incomplete [unclean_end].
     - Each state agrees with a fresh process, so `now` and the socket are re-evaluated on every request.
   - Rotation and rename (new path means a full read), replacement (inode, size, mtime or ctime change, plus the header and BOOT memcmp before an append), restart truncation, retention removal and a newly appearing boot all fall back to a full scan or drop the file. The C cache test covers each of these against a fresh read.
