## Facts from the diagnosis
- F1. The daemon opens a capture_loss gap when ANY of 15 counter-vector components moves (lifecycle fork/init/exit drops, wait_read_fail, event_ring_drop, writer_push_fail, ...). The tests watch one of the 15.
- F2. The withheld range runs from the last watermark's floor_db (the oldest last-record time of any non-idle backend) to the detecting tick. A backend that makes no transition (pure CPU) pins floor_db at its start, so one bad tick withholds everything since then, for every process, pid filters included.
- F3. Reproduced: one process with a 2.23 ms untraced lifetime (`lifecycle_init_lost_total` 0->1, nothing else moved) withheld 21 s; in round 13 the same shape withheld 15 s.
- F4. Reproduced: a ring drop detected only at the final SEAL tick withholds the whole test window, while the counter movement is observed after the window's end.
- F5. test_query_event Mode B (live CLI, no server): one dropped wait-end ring record removed one query row; the live CLI prints nothing about dropped events on stdout or stderr; the same code is on master.
