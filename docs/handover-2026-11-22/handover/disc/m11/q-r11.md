The review measured with the real writer and reader that a file cut between that END and the rollback OPEN reads complete for windows the END covers (it used a real watermark). Before delta 7 the implementation published FRONTIER first and END after it, which has no such window (a cut between them leaves the gap open). (a) Is D7 a file that claims completeness the capture never committed, i.e. a wrong number under a crash or a full disk (the rollback OPEN is itself a write that can fail), or does something else in the reader bound it? State exactly what the reader needs to return complete and whether those records can exist at that cut in a real capture. (b) Which order is right: END before FRONTIER (rows N14, V4, the 7b decision A3), FRONTIER before END, or END made conditional on a later record (so an END with no following FRONTIER or watermark is not a closure)? Give the smallest change (contract sentence, reader rule or writer order) that leaves no cut point at which the reader returns complete for an uncommitted closure, and say which existing rows change.
