# Opus: is discovery admission oversized? (one answer)
READ: origin/master contracts/merge-v1/CONTRACT.md §§3-6 (L81-130, L131-200, L296-557), coverage-a2-v1/CONTRACT.md (all 139), oracle-discovery/ROWS.md (token counts), `gh issue view 988`, memory owner-decisions-bba. NOT READ: branch code, spec-frozen.md, review files (I only grepped them), REWORK_PLAN. Default (non-exact_perf) transport behaviour: NOT SEARCHED.

**1. What it adds.** Without it, under exact_perf, records of processes running at tracer start carry no cookie and are dropped; that includes the auxiliaries, which live as long as the postmaster, so "the coverage record keeps every window Unavailable" (VERIFIED: issue 988 body). So the fallback is not "estimates until they reconnect". It is every window Unavailable, forever, on every server, because the checkpointer, bgwriter and walwriter never reconnect. Candidate (a) as worded therefore fails (INFERRED from that sentence). What discovery buys: windows become numeric from `P_close`, roughly seconds after start (VERIFIED: D41 L468ff defines `[boot_start,P_close)` unavailable). Frequency: every start of the tracer, not a rare pool corner (INFERRED).

**2. Is the design near minimal? No.** The root decision is one global startup gap that closes only when every inventoried lifetime has an exact proof: `C_close=max(census, b_i, x_i)` (VERIFIED: D41). Then any idle or failed lifetime holds the whole capture Unavailable, and each way a lifetime can fail to resolve quickly becomes a proof route, each with its own rows:
- Route 37(a), first fresh record after enable: ESSENTIAL. It is the same rule as 25b/25c, which already exists (VERIFIED: L119-121, L363-364).
- 37(b), quiet bracket: NOT essential. It exists only because an idle ClientRead backend may not transition for minutes. It brings wait_task_inactive qualification, voluntary-switch equality, the CPU seed, CONFIRM_DISCOVERY, retries (D38) and a measured "shell subjects, not PostgreSQL" basis (VERIFIED: L366-406, L298, D44). It appears in 44 rows using `B_D` and 22 using `TRY_` (VERIFIED: grep -c on ROWS.md; the token counts overlap).
- 37(c), no-wait-word route, about 10 rows: NOT essential. The owner already ruled the PG13 logger, stats collector and archiver "not backends: not listed, not counted" (VERIFIED: D43 text plus the memory note). A role filter at census time replaces the route (INFERRED).
- Exact terminal discharge, numeric-only/cookie-less EXITs, TERMINAL_UNRESOLVED, J witness: about 53 rows mention TERM/EXIT (VERIFIED: grep). These are needed only because closure wants the exact `x_i`. A conservative upper bound would do: the kernel EXIT time, or the instant the (pid,start_time) pair was seen gone. A lifetime cannot emit after its exit, so an upper bound only keeps the gap open longer, which is fail-closed (INFERRED).
- ABANDON (D45, 20 rows using `AB_`): NOT essential. An unbound lifetime simply stays uncertified until it exits (INFERRED).
- Forward-only latch, revocation of committed proofs, late-unlisted revocation (20 rows): these exist because proofs commit as separate controls beside the release stream and can be refuted later. If a bound is just a released record behind the frontier, a contradiction is an ordinary seal violation, which means VOID (INFERRED). Today's latch also makes any VOID leave windows Unavailable for the rest of the capture (VERIFIED: D43 latch sentence). That is a worse user outcome than the simple design.
Verdict: about 150 of 192 rows cover corners that a "make it impossible" rule removes (INFERRED, from the token counts above).

**3. Simpler designs (all fail closed).**
S1. Route (a) plus a nudge. Rule: census after F0 (keep D31-35: cookie partition, binding, map). Exclude non-slot roles. Send SIGUSR1 once to each slot-holding pre-existing process. PG's handler sets the latch, the wait loop does wait_end/wait_start, and that write is the 37(a) fresh record (INFERRED from PG source knowledge, not read here; exclude the syslogger, where SIGUSR1 rotates logs). User sees "startup: N pre-existing backends being attached"; numbers within about a second. Deletes 37(b), 37(c), D38, D40 exactness, D45, the latch (VOID becomes "re-run startup": re-census and reopen the gap at the VOID instant, which also makes REARM a production path). Loses the earliest-instant proof for idle tasks; nothing a DBA sees. Reuses the producer map/binding, the merge 37(a) path, the census, the startup-gap code and the enum harness (re-run on the smaller state space).
S2. Like S1 without the nudge. The gap closes when the last idle backend first transitions or exits. The UI names the pids it is waiting for. The deletions are the same as S1's. It loses up to the pool idle/lifetime timeout (often 10-60 min; INFERRED). It needs no signal to the customer database.
S3. Candidate (c), per-window certification, is NOT simpler. With time-ordered bounds, "a window is complete iff no unbound lifetime overlaps it" is exactly the global gap ending at max(bound) (INFERRED). Reject it.

**4. Process.** Yes, the process is part of the problem. Nine amendments in five days (VERIFIED: 6 contract commits #991-#1003 plus deltas 2-9 in ls-tree) each closed a corner by adding a row. The rising count of corners was the signal to cut the state space. On 20 Nov the lead should have asked "what is the smallest rule under which no lifetime can fail to resolve, and what does the DBA lose?" before freezing three routes; the memory "ask for the smallest shape first" already said this. Today: stop the rounds on all four branches. Put S1-vs-S2 (signal the database or not) to both advisers, then to the owner as one a/b question. Rewrite §6 as about 8 decisions with about 40 rows. Do not patch in place.

**5. Recommendation: switch to S1 (S2 if the owner refuses signals). Do not use a hybrid.** Once the nudge exists, the quiet bracket buys nothing a user sees, so keeping it "for later" keeps the cost. Switching costs one contract rewrite plus re-answers and the deletion of the 37(b)/(c)/D40/D45 code (INFERRED: smaller than the open rounds). What the owner gets: correct numbers seconds after start, and recovery after a fault instead of permanent Unavailable. This design can converge; the current one shows no sign of converging (INFERRED).
