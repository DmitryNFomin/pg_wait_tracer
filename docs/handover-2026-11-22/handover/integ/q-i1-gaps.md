## The three gaps
1. **A held cookie-less EXIT that matches only a numeric observation.** The coordinator's liveness rule must finalise undecided terminals so ordinary backends are not held indefinitely; TERMINAL_UNRESOLVED must name an inventoried identity with its reserved cookie; a numeric observation reserves no cookie. So under permanent loss of reconciliation, an EXIT held for a number can never be disposed. Options: (a) a capture disposition API naming the EXIT by its transport identity (source, position, pid, time) that consumes it as uncovered and leaves the number pending; (b) the contract lets such an EXIT pass as an ordinary uncovered cookie-less record once the number's resolution is permanently impossible; (c) something else. Which is sound under DECISIONs 31, 40 and the latch, what exactly is the trigger, and does it need a contract sentence and a row?
2. **Acceptance versus commitment.** The specification asks the coordinator to track attempted delivery, accepted control and committed outcome separately. The accessor exposes admitted, abandoned, confirmed bound and terminal released, but not "CONFIRM accepted and pending" nor "terminal disposition accepted, not yet discharged". Is that distinction needed for any decision the coordinator makes (name the decision), or only for diagnostics? If needed: the smallest addition (fields in pgwt_discovery_state, or a return code).
3. **Pointer continuity is a Boolean with no "unknown".** The translation rule says supply continuity only when known and never encode unknown as a demonstrated break; the coordinator currently passes true (no break) when unknown and still delivers a qualified non-NULL observation. Is passing true sound (can unknown continuity let a no-wait-word bound commit or survive that should not)? If not: a three-valued field honoured by which guards, and the rows it needs.

For each: must it be decided before the next coordinator round (transport receipt, membership, terminal join) or can it ride with the daemon-wiring round? And can the three ride in the merge side's next round as one small interface change?
