## Challenge
1. **Is "holds a process slot" observable with what the tracer has, on every supported version (13, 17, 18) and on both kernels (4.18, 6.8)?** For acquisition and for relinquishment separately: the exact observable (a probe site, a pointer becoming non-NULL at a known address, an exit), whether it can be missed (ring loss, a process killed between fork and InitProcess, an auxiliary that uses InitAuxiliaryProcess, a walsender, a background worker, a process that acquires and exits within one tick), and what the tracer can truthfully say when it is missed.
2. **The draft's entry-time cohort key** (writer boot and a time bucket of slot entry): what is it for, is it needed for the owner's decision, and is there a smaller rule that gives the same counted population (for example: counted from the first record that proves the slot until the EXIT, with no cohort at all)?
3. **Where the rule lives.** One sentence in merge-v1 (which DECISION), one in coverage-a2-v1 (the note and limit for untraced short backends: does "not a backend" change what is counted against that limit), or a new contract? Which existing oracle rows change their expected output under the rule, if any (name them), and how many new rows does the smallest version need (the draft has twelve).
4. **What the interface and the documentation must say** so that a user is never shown a count that silently excludes something: the sentence for the README, and what the UI shows for a connection that never took a slot (nothing; a separate "connections that never became backends" count; a note).
5. **Order and size.** Is this one unit or two (contract, then producer and merge together; or producer evidence first), what does it depend on among the units in flight (the producer's P1 fix round and P2, the merge side, the coordinator), and can the churn exception of issue 959 be removed only after it or independently.
6. **Verdict:** proceed with the draft as is / proceed with these exact changes / send back for a smaller design; and the three things most likely to be wrong in the draft.
