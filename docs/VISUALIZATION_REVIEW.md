# pg_wait_tracer — Web UI visualization review

_Reviewed at v0.13 (master 92d56ce, 2026-07). Findings cite file:line; each was verified against the code before inclusion._

_Amended 2026-07-31: the interaction-model question this review did not ask — request/response repaint vs a camera over client-resident data — is answered in `docs/INSTRUMENT_ARCHITECTURE.md`, which revises §7's "full stop" verdict and upgrades Phase 2 (its §6 lists the precise amendments)._

## 1. Executive verdict

**Is ECharts the right library? Yes — the perceived library limitation is a misdiagnosis.** The codebase uses maybe a quarter of ECharts' relevant surface: a grep across `web/static` (excluding vendor) finds **zero** `chart.on()` handlers, zero `dataZoom`, zero `brush`, zero `toolbox`, no time-type axes, no `echarts.connect`. Every capability the missing interactions need — click events, in-chart zoom, piecewise/log visualMap, linked cursors — ships in the vendored 5.5.1 bundle unused. The two interaction features that do exist (drag-zoom, external legend) were hand-rolled *beside* ECharts rather than *with* it. Meanwhile the places ECharts earns its keep are exactly where hand-rolling is expensive: the custom-series Gantt renderItem (pure, unit-tested against a fake api — `web/static/lib/builders/timeline.js:19-34`), heatmap+visualMap, tooltips/axes/resize, and `convertFromPixel` powering the app's own selection overlay. Migrating would forfeit the 16 option-pinning unit suites and every pixel baseline simultaneously — the highest-risk possible move for a project whose scarcest resource is visual testability — and would carry every actual defect along, because almost all of them are generated above the library.

**Is this the best possible way to present this information? The composition is right; three layers under it are broken, and one dimension of the question was never finished.** The skeleton — persistent stacked-area AAS by wait class with a fixed semantic palette (`lib/format.js:10-22`), N-CPUs reference line, drag-select time zoom re-ranking top-N tables, class→event→query/pid drill with breadcrumbs, and a genuinely rare honesty layer that shades sampled regions and refuses to fabricate — *is* the Oracle EM / RDS Performance Insights composition. Keep it. What is broken: (1) **failure visibility** — build/mount exceptions and every server-side command error vanish into four silent catch sites, so a broken pane, a stale pane, and an idle database are pixel-identical; (2) **perceptual stability** — event colors have no identity, legend selection is index-keyed, all trust annotations ride `series[0]`, and the escalation edge-line is placed at a coordinate the axis cannot show (it has literally never rendered); (3) **interaction asymmetry** — every table row is a drill intent but no chart mark anywhere is clickable. And the incomplete dimension: nobody can *compare* this window to a normal one (the canonical end of every ASH investigation), the filter model is exactly `{class, event_id, pid, query_id}` with no database/user/application slice, and the fidelity marker exists only beside the AAS chart while the tables present sampled-scaled estimates identically to exact numbers.

**How real is the drill-down story? The plumbing is substantially better than the UI.** One global FilterStack (`lib/state.js:104-147`) is sent by all nine views and honored uniformly by the C server (`src/server.c:256-281`, pushdowns at 1586, 2005-2007), time is global, and breadcrumbs even restore the source view on drill-up — a detail commercial tools get wrong. So "brush the time range → everything re-ranks" genuinely works today, and class→Sessions, query→Timeline, event→Histogram all *function* — but only if you know the secret that tabs are filter-preserving lenses, because the PIVOT map (`app.js:413`) advertises exactly four one-way corridors. The rest of the gap is interaction surface: inert charts, no URL state (F5 destroys the entire investigation), and a live loop that keeps re-ranking tables under your cursor because `drill()` — unlike zoom — never pauses it. The distance to a genuine ASH loop is about seven small wires, not an architecture.

**Why do charts "look weird", and why is that hard to articulate? Because the defects are mechanical instabilities without names, and there is no place to isolate them.** The same wait event changes color and stack position every 5 seconds after a class drill (index-keyed palette over server-rank-ordered series). Hovering a legend chip makes the N-CPUs line and the "this data is estimated" shading vanish (verified empirically by SSR-rendering the vendored bundle). A burst marker for the most recent burst plots at the far *left* of the chart. Timeline bars paint over the PID axis labels. The y-axis breathes on live ticks and flattens a real lock storm to a 3% sliver on a 64-vCPU host. None of these are subtle once named — but the only way to see any chart on known data is a full Playwright run (the mock's WebSocket lives on port+1 while `app.js:158` hardcodes `location.host`, and the workaround is a monkey-patch copy-pasted five times), and the pixel oracle tolerates ~10,000 arbitrary pixel changes per region. **"Hard to articulate" is downstream of "impossible to isolate."** Fix the isolation loop and the vocabulary, and the weirdness becomes a bug list.

## 2. What is genuinely good

Keep these; they are the reason every fix below is cheap.

- **The pure-builder architecture.** Data in → ECharts option out, no DOM, Node-importable, with explicit empty-state contracts (`{option:null, hasData:false}`) and pinned fidelity color constants. Most teams never get here. It is also the roadmap's own escape hatch: builders emit view models, "only mount speaks ECharts" (`docs/ROADMAP_AND_STATUS.md:202`).
- **The four-layer test pyramid, honestly documented.** 15-16 sub-second `node --test` suites pinning exact option structures; Playwright functional; a deterministic seeded chaos suite with an *empty* XFAIL list; pixel baselines. Each layer states what the layer below cannot see.
- **The transport/state core.** Single-flight, epoch chokepoint, soft resync — the machinery that killed the old `_refreshGen` race bugs. `TimeRange`/`FilterStack` are pure serializable data, which is why URL state is ~50 lines away.
- **The honesty layer where it exists.** Sampled-region shading, the never-fabricate escalation rule (UI-10), the histogram's refusal panel over sampled windows, the server's structured `window_too_large` errors with hints (DUR-9, `server.c:1636-1656`). No peer tool refuses to fabricate this carefully.
- **The composition itself.** AAS by class + CPU line + drag-zoom + re-ranking top-N tables + breadcrumbs-with-source-view is the correct ASH presentation. The table half of the app is close to gold standard.
- **The vendored-bundle discipline.** SHA-256 pinned, byte-verified, documented upgrade procedure. (The bundle is 5.5.1; the embedded zrender 5.6.0 version string is easy to misread as the ECharts version.)
- **The custom selection overlay** (`lib/selection.js`) — pure pixel→time math, unit- and chaos-tested, and explicitly designed for reuse on other time-axis charts. It is the ready-made zoom for the timeline and the B6 waterfall.

## 3. Confirmed problems

Deduplicated and ordered by how much they hurt the analyst.

### P1. Failure is invisible: broken ≡ empty ≡ stale (worst problem in the codebase)

**Symptom.** A pane silently shows the *previous* window's rows under a *fresh* time readout; or an eternal "Loading..."; or a blank table. The analyst reads it as "the database was idle" or as un-articulable weirdness. This is the single biggest contributor to both the debugging pain and the "looks weird" pain.

**Cause.** Four silent swallow sites: `lib/view-manager.js:112-115` (build throw → bare `return`), `:119-121` (mount throw), `app.js:333-334` (same pair for the persistent AAS view), and `app.js:243-246` (`onRequestError` drops every error with `transport:false` — i.e. **all** server-side command errors). `switchTab` writes a "Loading..." placeholder (`app.js:394`) nothing replaces on failure. Grep-verified: zero `console.*` calls in all non-vendor JS. The kicker: the server's DUR-9 `window_too_large` structured error — emitted by 13 handlers explicitly so "the client can present" it, reachable today via the shipped "24h"/"All" buttons — has **zero** client handling. The server pledges "NEVER a silent empty result" (`server.c:1625-1627`); the client silently discards the refusal. Latent fuse: `fmtPct`/`fmtAas`/`fmtCount` throw on null (`lib/format.js:87-94`), `pctBar` too (`lib/table.js:144`), fed unguarded by `overviewConfig` (`lib/builders/table-configs.js:30-34`) — currently held up only by the server always emitting numeric `pct` on those paths.

**Fix (~15 lines + a card).** `console.error` at every swallow site; render a per-pane error card (view, command, server `code`/`hint`, retry) for build/mount throws and `transport:false` envelopes — the `panels.js` unavailable-panel machinery already proves the pattern. Null-guard the formatters to "—" like `fmtMs`/`fmtUs` already do. Update the Playwright console-error guard to allowlist/assert the error surface instead of forbidding all logging — the current guard is *why* nobody dares log.

### P2. The flagship AAS chart has no stable identity, and its trust annotations vanish on hover

**Symptom.** Drill into a class in live mode: the same wait event changes color and stack position every 5 seconds (abrupt flash — `animation:false`). Hover or solo any legend chip: the N-CPUs line and the amber "sampled = estimated" shading silently disappear while the fidelity chip beside the chart keeps describing shading that is no longer on screen. And the "Escalated (manual/anomaly)" edge line has **never rendered in any state**.

**Cause.** Three interacting mechanisms, all verified (two empirically via Node SSR of the actual vendored bundle):
- Colors by array position: `aas.js:35-39` assigns `EVENT_PALETTE[idx % 16]` while the server re-ranks top-16 events by total AAS per window every tick (`src/compute.c:504-527`). The same events are class-colored in the DFG (`builders/transitions.js:69`) and stacked bars (`lib/table.js:177`) — so IO events render tomato/limegreen/gold in the AAS breakdown (hues that mean Lock/CPU/Client everywhere else) and IO-blue elsewhere.
- Legend selection is a Set of series **indices** persisting across refreshes and the class↔event mode switch (`views/active.js:28, 187-188, 207-240`); a CPU solo becomes an arbitrary-event solo after a drill, and if a tick returns >11 event series, series 11-15 are hidden with zero user action — the stacked total then silently understates AAS.
- All annotations ride `series[0]` (`aas.js:113-120`, rationale comment at `:84-87` admits it exists to keep test assertions clean): legend-unselecting CPU — which plain hover-solo does (`active.js:216-224`) — removes the fidelity band, escalation band, and N-CPUs line together.
- The escalation markLine is placed at `win.to` (`aas.js:99-111`, `fidelity.js:171, 189-202`) but the x-axis max is the last bucket **start** (`aas.js:55-56`; `compute.c:381`), always `< to` — ECharts drops out-of-range markLines entirely. For a page loaded mid-escalation, that line is the *only* intended annotation (UI-10), so the chart shows nothing. Unit tests pin the broken coordinate (`fidelity.test.mjs:118,147`).

**Fix.** One color-assignment service: event → deterministic tint within its class hue (retire `EVENT_PALETTE`); stable client-side stack order by event identity. Key legend selection by series **name**, reset on series-set change. Move all marks to a dedicated `{type:'line', data:[], silent:true}` annotation series excluded from `seriesNames`/`legend.data` (empirically verified to fix the vanishing). Pin the x-axis to `[win.from, win.to]` or clamp mark coordinates to axis range, with a unit-test invariant. Flip the tests that currently enshrine the bugs (`aas.test.mjs:70` pins index colors; `aas.test.mjs:48-56` pins series[0] marks).

### P3. Charts are drill dead-ends; the cross-filter fabric is a secret

**Symptom.** You spot the anomaly on a chart and cannot pursue it there. The timeline says "Zoom in for more detail" on a chart with no zoom (`views/timeline.js:59-62`). Burst rows can't jump to the burst. DFG nodes, heatmap cells, timeline bars: tooltips, no clicks. The events table shows P50/P95/P99 (`table-configs.js:55-58`) but row-click goes to queries, never the histogram that visualizes that exact distribution. Meanwhile the *working* pivots (class→Sessions, query→Timeline, event→Histogram) exist only as unadvertised filter-preserving tab switches — README.md:361-363 documents a drill chain that doesn't even match the actual PIVOT.

**Cause.** Zero `chart.on()` anywhere; PIVOT (`app.js:413`) hardwires one destination per key; burst/peak tables are inert `innerHTML` bypassing `lib/table.js` (`views/concurrency.js:66`, `builders/concurrency.js:88-115`); histogram runs a parallel one-way filter state in DOM `<select>`s (`views/histogram.js:33-40, 83-107`) invisible to breadcrumbs and clobbered by live ticks; tab buttons carry no filtered-state indication.

**Fix.** Seven wires, all through the existing `ctx.onDrill`/`ctx.onZoom` intent plumbing: (1) `chart.on('click')` on AAS series → class drill (event drill in breakdown mode); (2) burst/peak rows → `zoomTo(burst ± pad)` — the single best value-per-line change in the app (bursts are 4+ sessions in 10ms; drag-select at a 15-min window resolves ~1s/pixel, so this is genuinely unreachable today); (3) reuse `attachSelection` on the timeline x-axis (its header says it's reusable; note inside-dataZoom is the *wrong* mechanism — server-side coalescing means detail needs a refetch); (4) heatmap cell → event+time drill; (5) DFG node → event drill (needs the server to emit `event_id` in node JSON — it's in the hash table at `server.c:2563`, one line); (6) events percentile cells → histogram tab; (7) a persistent filter bar + tab badges making "tabs are lenses" visible, and histogram dropdowns writing through to FilterStack (deleting the second source of truth).

### P4. Live mode fights the investigation

**Symptom.** You drill into a spike; every 5 seconds the tables re-rank and re-mount under your cursor, a click lands on a different row than you aimed at, an open tooltip is clobbered, and the anomaly slides out of the re-anchoring window.

**Cause.** `drill()` (`app.js:415-422`) contains no `stopAutoRefresh` — unlike zoom (`:115`), dblclick zoom-out (`:352`), custom range (`:592`). The app boots live (`startAutoRefresh(900)`, `:211`); each tick re-anchors to NOW and `mountTable` full-`innerHTML`-replaces (`lib/table.js:82`). Bonus inconsistencies: tab-pauses-live is a hardcoded string check (`app.js:391`), and the Live button silently forces a 300s span vs the 900s boot default (`:653` vs `:211`) despite `timeRange.liveRangeSecs` already existing.

**Fix.** Pause live on any investigation gesture (drill, breadcrumb) exactly as zoom does; Live button is the explicit way back (re-anchoring to NOW, honoring the project's live-means-NOW rule) and keeps the current span; move the pauses-live property onto view objects. Note `view-manager.js:82` already documents an unused `opts.userInitiated` hook for exactly this — the design anticipated it and never wired it.

### P5. Chart lifecycle churn: dispose/re-init, default animation, legend rebuilt mid-hover

**Symptom.** The live-followed session timeline tears down and rebuilds every 5s (drill-to-pid does *not* stop live), destroying open tooltips and hover state. Dragging the DFG "Simplify" slider fires dozens of full dispose/init/re-layout cycles per drag, replays node pop-in, resets roam/pan, and snaps back every node you dragged (`draggable:true` promised, discarded). The concurrency line replays its ~1s draw-in on every tab entry/zoom. A mid-hover AAS legend refresh *cancels* your hover-solo (the chart pops back to all series under a stationary cursor).

**Cause.** `views/timeline.js:69-71`, `views/concurrency.js:62-64`: `disposeChart() + echarts.init + setOption(_, true)` on every mount; `view-manager.js:120` calls mount on every refresh. `views/transitions.js:118-121` wires the unthrottled slider `input` to a full rebuild (`:40-53`); `builders/transitions.js:74` bakes container pixel dims into node coords while `resize()` only calls `chart.resize()` (`:132`) — stale layout after window resize. Only `aas.js:124` sets `animation:false`. Legend `innerHTML` + listeners rebuilt every refresh (`active.js:198-240`). Scope corrections that keep this honest: the main live AAS chart already does it right (persistent instance, `animation:false`); the timeline custom series has no entry animation (the artifact is teardown flash + tooltip loss, not from-zero wipes); concurrency/transitions are off the live loop by default (`app.js:391`), re-enabled only via the quick-range/Live-button edge paths (`:566-580`, `:649-657`).

**Fix.** Adopt the histogram view's proven pattern everywhere (lazy init once + `setOption` on refresh, `views/histogram.js:64-65` — requires stabilizing the DOM shell like its `ensureShell`); `animation:false` in every builder, pinned by one assert each; throttle the slider to rAF and update only links on the persisted instance; preserve dragged node coords (read back before re-layout — note `getOption()` may need a mouseup capture for `layout:'none'`); re-run layout, not just `chart.resize()`, on resize; event-delegate the legend and batch visibility into one `setOption({legend:{selected}})` instead of N dispatches per hover.

### P6. Marks plotted at the wrong place: burst markers and bleeding timeline bars

**Symptom.** "There's a red burst triangle at the start of the chart that matches nothing in the table" — for exactly the burst you care about most (the latest). "Colored bars are drawn on top of the PID axis labels / bleed off the left of the chart" — routine, since long lock waits and ClientRead spans that started before the window are the norm.

**Cause.** `builders/concurrency.js:32-35`: `findIndex(p => p.t >= b.timestamp_ns)` returns −1 for any burst inside the final bucket (peak `t` values are bucket *starts*, `server.c:2789`), and `Math.max(0, idx)` clamps it to bucket 0 — empirically reproduced: coord `[0, …]`, wrong x *and* wrong y, directly contradicting the correct time in the table below. In-range bursts are also off-by-one (bucket *after* the containing one) — and the unit test pins that off-by-one as correct (`concurrency.test.mjs:39-47`). Timeline: `type:'custom'` series defaults to `clip:false` in this bundle (verified: `defaultOption={...,clip:!1}`), the renderItem draws from raw unclamped starts (`builders/timeline.js:19-33`), and the server emits `pending.start_ns = timestamp − duration` with no clamp to `from_ns` (`server.c:2476, 2493`) — rects extend left across the 100px margin over the "PID n" labels at z above the axis.

**Fix.** Burst: arithmetic containing-bucket `clamp(floor((ts − peaks[0].t)/bucket_ns), 0, n−1)` (`bucket_ns` is already in the response) + a last-bucket unit test; longer term a value-type time axis so markers sit at true timestamps. Timeline: `clip:true` (one line) **and** clamp `[s, s+d]` to `[opts.from, opts.to]` in the builder so widths and the 1px-minimum logic stay correct (keep the raw start for the tooltip); unit test with a pre-window start.

### P7. AAS y-axis policy: flattening, no rescale on solo, breathing

**Symptom.** On a 64-vCPU host with AAS ≈ 3, the entire stacked area occupies ~3% of chart height under a dominant red "64 CPUs" line; a 2×→6× lock storm is a ripple. Soloing a small class keeps the stale axis, rendering it unreadable. Above ~1.25× CPU load, the axis max pops every 5s tick; and because buckets re-anchor to a shifting `from` (`state.js` anchorLive; `compute.c:371-381`), the waveform shape shimmers even on unchanged data.

**Cause.** `aas.js:49-53`: `yMax = max(maxAas*1.2, numCpus*1.5, 1)`, baked at build; the legend path only dispatches actions, never rebuilds; the live window is never quantized to bucket boundaries.

**Fix.** Cap the CPU line's influence — `yMax = max(maxAas*1.2, min(numCpus*1.5, maxAas*4), 1)` — and show the reference off-scale ("64 CPUs ↑" at the top edge) when load is far below capacity; hysterese/round yMax (grow immediately, shrink after N stable ticks); rebuild on legend-selection change; quantize `from`/`to` to bucket multiples so re-binning is phase-stable. (Honesty note: RDS PI flattens the same way — the peer precedent cuts both directions; data legibility should still win.)

### P8. Heatmap: linear rainbow on heavy-tailed counts, global rescale each tick, dropdown clobber

**Symptom.** One hot cell drives `max_count` and every other cell collapses into the two darkest blues — the distribution-shift question this EXACT-tier view exists to answer becomes unreadable. In live mode every cell recolors every 5s as the sliding max moves, and an open class/event dropdown snaps shut mid-selection.

**Cause.** `builders/histogram.js:18-19, 53-58`: linear visualMap 0→`max_count` over a 6-stop rainbow whose hues (blue/green/red/orange/yellow) collide with 5 of the semantic class hues; log2 latency bands make heavy tails structural. Per-tick `<option>` rebuilds at `views/histogram.js:78, 98`.

**Fix.** Map color on `log1p(count)` (tooltip keeps raw counts) with a single-hue perceptually-ordered ramp that cannot be read as class identity; sticky `visualMap.max` (recompute on window change, not per tick); skip selector rebuild when `document.activeElement` is a select. Pure builder edits with existing unit + snapshot coverage. Highest-leverage single fix for "the heatmap looks weird."

### P9. Zero URL state: investigations cannot be bookmarked, shared, reloaded, or retraced

**Symptom.** F5 resets to overview + live 15m; back/forward do nothing; one ✕ click (`app.js:431-436`) irreversibly destroys the drill path; "here's where the problem is — look" cannot be a link. Grep-verified: no pushState/hash/popstate/URLSearchParams anywhere; no storage either.

**Fix.** Serialize `{tab, from, to, live|span, filters, sort}` to the hash on every state change; hydrate in the `!uiInitialized` branch of `onConnected` (where `initDefault` runs today). `TimeRange`/`FilterStack` are already pure JSON-shaped — this is ~50 lines. Two implementer notes: serialize ns timestamps as strings (they exceed 2^53), and a restored `live=1` must re-anchor to NOW per the live-means-NOW rule. Side benefit: deep-link entry gives the snapshot suite deterministic access to drilled/sorted states, which currently have almost no visual coverage. (Caveat kept honest: the per-user SSH bridge means cross-user links need the colleague running their own bridge; single-user value is unaffected.)

### P10. The fidelity story stops at the AAS chart (Trust-Milestone blind spot)

**Symptom.** In a sampled/mixed window, the tables' DB-time/AAS numbers are scaled estimates presented pixel-identically to exact ones; the events table's P50/P95/P99 are computed from `exact_count` only (`src/compute.c:876ff` deliberately excludes sampled events) — over a mostly-sampled window those percentiles describe a small exact subset with no indication of that basis.

**Cause.** Verified: zero fidelity/sampled references in `events.js`, `queries.js`, `sessions.js`, `overview.js`; the fidelity chip renders only beside the AAS chart.

**Fix.** A per-pane fidelity badge (reusing the existing chip model) and an explicit basis footnote on the percentile columns ("percentiles from exact-captured events only: N of M"). Related honesty gap: only the timeline states truncation ("Showing N of M"); the summary tier caps entities (`SUMMARY_MAX_EVENTS`/`SUMMARY_MAX_QUERIES`, `compute.c:1389/1412`) and the tables silently omit the tail — add an "N others" row or a completeness line.

### P11. Minor but real (fix opportunistically, mostly inside the fixes above)

- Stacked composition bars distort: <0.5% segments reappear inside a gray "Other" that conflates skipped-known with genuinely-other; `min-width:2px` per segment lets widths sum past 100% and flex silently renormalizes; same-class events fuse into one indistinguishable block with no separators (`lib/table.js:147-191`, `style.css:383-397`; same clamp pattern in `builders/transitions.js:150`). Fix: 1px separators, honest remainder labeling, pre-normalize widths in the builder, event tints from the P2 color service.
- Sticky query columns: col-1 pinned at hard-coded `left:160px` while col-0 floats 80-160px (`style.css:327-343`) — a see-through slot scrolled text slides through. Fix col-0 to an exact width.
- Drag-select starts anywhere on the container, including over axis labels, and extrapolates out-of-grid pixels (`lib/selection.js:95, 24-38`). Guard with `chart.containPixel('grid', …)`, clamp, `preventDefault`, Escape-to-cancel.
- Time formatting: no date component anywhere (24h windows wrap midnight ambiguously); sub-second zoom reads "HH:MM:SS – HH:MM:SS (0s)" while being correct; AAS tooltip percentages independently rounded sum to 97-103% (`aas.js:194`); chart coordinates are raw ns epochs (~1.77e18, double ulp ~256ns) — convert chart-space time to ms at the builder boundary.
- Timeline 1px floor equalizes 5µs and 5ms waits (`builders/timeline.js:27`); `pidIndexMap[ev.p] || 0` misattributes overflow-PID events (server caps pids at 256, `server.c:2350-2370`) to row 0.
- CVD: `EVENT_PALETTE` (`format.js:31-36`) is severely colorblind-hostile (retired by P2); fidelity tint bands are faintest exactly where the chart is busiest — add a decal/hatch or an always-visible fidelity strip.
- Three parallel copies of the dark theme (CSS, `'dark'` init theme, per-builder chrome repeated in five builders) and a stale comment claiming an ECharts brush component exists (`style.css:185`). Consolidated by the chassis (Section 8).

## 4. The "looks weird" decoder

Seven words. When something looks wrong, name which of these it violates — each maps to confirmed instances in this codebase:

- **STABILITY** — the same identity keeps the same color/position/selection across refresh, sort, and drill. *Violations:* index-keyed event colors and stack order (P2); index-keyed legend Set soloing the wrong series (P2); yMax breathing and bucket phase shimmer (P7); heatmap global recolor per tick (P8); DFG dragged positions discarded (P5); dropdown clobbered mid-selection (P8).
- **CONTINUITY** — tick N → N+1 is a smooth update, never a teardown. *Violations:* dispose/re-init flash and tooltip loss on the live timeline (P5); slider-drag rebuild storms (P5); mid-hover legend rebuild canceling your solo (P5).
- **ALIGNMENT** — every mark sits where its data says, inside the axes. *Violations:* burst triangle at bucket 0 for last-bucket bursts (P6); escalation markLine placed past axis max, never painted (P2); timeline bars over the PID labels (P6); the 160px sticky-column slot (P11).
- **OCCLUSION** — nothing overlaps or clips at dense data. *Violations:* DFG pixel-baked layout bunching after resize (P5); no `hideOverlap` outside aas.js; same-class bar segments fusing (P11).
- **SEMANTICS** — an encoding means the same thing everywhere. *Violations:* rainbow heatmap ramp reusing class hues as intensity (P8); EVENT_PALETTE hues colliding with class meanings (P2); "Other" conflating two meanings; 1px floor making µs ≡ ms; min-width renormalization breaking proportion=value (P11).
- **HIERARCHY** — visual weight matches analytical importance. *Violations:* a reference line dominating a flattened data sliver (P7); the honesty shading faintest during busy periods; error states carrying zero visual weight (P1).
- **FEEDBACK** — every failure/empty/stale/truncated state is visually distinct and labeled. *Violations:* all of P1; silent table truncation (P10); the fidelity chip describing shading that isn't on screen (P2).

Write these into `docs/VISUAL_CHECKLIST.md` with the gallery cell (Section 6) that exercises each. Bug reports then read "STABILITY violation, gallery cell aas/event-breakdown, tick 2" instead of "looks weird."

## 5. Drill-down gap analysis

**The target loop:** notice (spike on AAS) → localize (brush the time) → attribute (dimensions re-rank) → isolate (drill class → event → query/session) → inspect (timeline / latency distribution / executions) → **compare** (vs a normal window) → **share** (a link).

**Today:** notice ✓. Localize ✓ — drag-brush genuinely re-windows everything (unsignposted). Attribute ✓ — the strongest part; all nine views honor the global filter, and this works better than most commercial tools. Isolate: tables-only, four advertised edges, the rich real fabric hidden (P3, P10-discoverability). Inspect: exists but terminus views dead-end (no timeline zoom, no burst jump, no per-execution list for a drilled query — the server's raw-event model appears to support one). Compare: **absent entirely** — no two-window overlay/diff anywhere, and this is the largest capability gap in the whole "best possible way" question; every ASH peer ends here (AWR Compare, PI compare ranges). Share: absent (P9; no CSV/PNG export either — the only extraction method is an OS screenshot).

**Minimal missing-link set, in value order:** (1) surface command errors (P1); (2) URL state (P9); (3) AAS `chart.on('click')` → drill; (4) burst rows → `zoomTo`; (5) pause live on drill (P4); (6) timeline zoom via `attachSelection` refetch; (7) filter bar + tab badges. With those seven the UI runs the full loop minus compare. Compare is the one genuinely *new* capability to design after URL state lands (it is the prerequisite).

**Two completeness questions the UI should answer explicitly:** the dimension set is `{class, event_id, pid, query_id}` — peers also slice by database/user/application. If that is a BPF capture constraint, say so in the UI/docs; if not, it is a presentation gap worth a roadmap line. And nothing in the UI teaches its own language — drag-to-zoom is invisible until attempted, the amber shading and the CPU*/Off-CPU* asterisks are unexplained. A small "?" glossary is cheap and directly attacks "hard to articulate" from the user side.

## 6. The developer loop that fixes the testing pain

Ranked by leverage per effort, all this-codebase-specific:

1. **Make failures loud (hours, ~15 lines).** P1's fix is also the debugging fix: every future rendering bug stops degrading to an unexplained blank pane.
2. **Make the mock human-reachable (hours).** `app.js:158` hardcodes `ws://location.host/ws`; the mock serves WS on port+1; the workaround is a 13-line monkey-patch copy-pasted exactly 5 times across the suites (`test_web_ui.py:1231/1519/1595`, chaos `:576`, snapshots `:141-152`). Add a `?ws=` param or a `ws_url` field in `/session` (both mock line 887-900 and app.js already speak `/session`), then delete all five copies. After this, "reproduce the bug" = "start the mock with the right env knobs and look."
3. **Fixture gallery (1-2 days) — the centerpiece.** `web/static/dev/gallery.html` + `tests/fixtures/*.mjs`: every pure builder × curated states — empty, single point, dense (300 buckets / 50 PIDs / 16+ events), degenerate (all-zero, one huge value, unicode names, hostile SQL), sampled/mixed/escalated fidelity — plus a recorded **live-tick sequence with a play button** replaying N payloads through the same builder+setOption path, so stability/continuity defects are eyeballable. Builders are pure ESM, echarts is vendored, the mock already has a static handler: this is nearly free, and it is where "weird" becomes articulable and reviewable.
4. **Pin playwright + record provenance (1 hour).** `ci.yml:220, 275` install playwright unversioned, so the gating chromium drifts from the Jun-17 baselines; `web_snapshots/README.md`'s claim that `playwright install` "pins" is false (it pins per-playwright-version only). 5. **Fix `run_all.sh` (30 min).** It never runs the sub-second `node --test` layer or `go test` (CI-only), and its local snapshot gate (`run_all.sh:251-256`) fires whenever Pillow imports — baselines are always committed, so any dev box runs a cross-environment pixel compare producing exactly the spurious red its own comment (`:246-250`) claims to prevent. ## 7. Library verdict & path

**Stay on ECharts as the renderer — for now** (amended 2026-07-31: the request/response *interaction model*, not the library, is the real gap; see `docs/INSTRUMENT_ARCHITECTURE.md`). Within the renderer question, the evidence: every felt limitation traces either to library features never adopted (click events, dataZoom, time axes, merge-mode setOption, piecewise visualMap) or to self-inflicted config (index palettes, series[0] annotations, dispose-per-refresh, linear rainbow). The places the code genuinely fights ECharts are narrow — the external legend's dispatch storm, the series[0] annotation hack, the DFG where `layout:'none'` means ECharts contributes only edges/roam/tooltips — and each has a cheap in-library fix already specified above. The DFG is the sole chart where another tool could plausibly win, and the roadmap already plans its scalable sibling (the transition matrix) — demote the DFG to small-graph duty rather than re-platforming it.

**The B6 views seal it:**
- **Per-execution waterfall** — explicitly planned as "same technique as the session timeline" (`docs/ROADMAP_AND_STATUS.md:216`); the custom-series renderItem is proven and unit-tested. Hard condition: it must ship with zoom (selection-overlay refetch) and click-to-inspect **in its definition of done**, or it repeats the current timeline's proven failure mode (a banner instructing an action the surface cannot perform).
- **Transition matrix** — a categorical heatmap; the histogram builder is the template. Use a log/piecewise visualMap from day one (don't inherit P8).
- **Latency scatter** — server-side density capping keeps counts bounded; ECharts large-mode scatter + built-in `type:'log'` y-axis cover it. Lasso is the only gap, and the repo already owns the answer: extend `pixelRangeToTime` to a 2D box (`convertFromPixel` already returns both axes) — the same pure-math, Node-testable pattern that replaced ApexCharts' zoom.

**Alternatives fail on engineering grounds:** uPlot is optimized for what this app doesn't do (streaming 100k-point series vs polling ≤300 pre-aggregated buckets) and is weakest at stacked areas — the AAS chart's entire identity; the 1.03MB go:embed'd, cached bundle is a non-cost, so don't slim it either. Vega-Lite/Plot preserve spec-testability but can't express the waterfall/DFG without escape-hatching. Hand-rolled canvas trades a maintained renderer's tooltips/hit-testing/axes for bespoke code a single maintainer debugs alone. Decisive and underweighted in any migration fantasy: **the test capital is ECharts-shaped** — 16 option-pinning suites, renderItem geometry tests against a fake api, and every pixel baseline die together in a migration. If a per-chart experiment is ever wanted, the roadmap already scoped the safe path: builders emit view models, only mount speaks ECharts, one view behind the existing seam — never wholesale.

**The path:** roughly two weeks of *adopting* the library instead of routing around it — click→intent wiring, selection-overlay zoom on time charts, persistent instances with `animation:false`, ms chart coordinates, name-keyed identity, a dedicated annotation series, one shared theme object. That worklist addresses more of "looks weird" than any migration could, because the weirdness is generated above the library.

## 8. Recommended plan

Sized for a single maintainer; each phase leaves the tree shippable.

**Phase 0 — quick wins (days).** P1 error paint + formatter null guards (+ console-guard allowlist update). Mock reachability (`?ws=`/`ws_url`), delete 5 monkey-patches. Pin playwright + VERSION file. `run_all.sh`: node tests in, local snapshots opt-in. Burst-marker arithmetic clamp + last-bucket test. Timeline `clip:true` + window clamp. Escalation markLine clamp/axis pin (+ flip `fidelity.test.mjs:118,147`). `animation:false` in every builder. Pause live on drill; unify the live span. Fix the tautological test assertion.

**Phase 1 — the seeing infrastructure (1-2 weeks).** Fixture gallery + live-tick replay. `VISUAL_CHECKLIST.md`. Then the identity cluster with before/after gallery cells: color service (event → class tint, retire EVENT_PALETTE), name-keyed legend selection with reset-on-set-change, dedicated silent annotation series (flip `aas.test.mjs:70, 48-56`, which currently pin the bugs). Gallery-cell snapshots with tight thresholds.

**Phase 2 — the chart chassis + drill wiring (weeks).** Extract one themed base option (kills the triplicated chrome), an instance-reuse mount helper with the animation policy, one time-axis convention (ms coordinates), and click→intent plumbing. Wire the seven drill links (Section 5), URL state, yMax policy + window quantization, heatmap ramp + sticky max, filter bar + tab badges, histogram write-through, per-pane fidelity badges + percentile-basis footnotes, table "N others" rows. DFG: persisted instance, throttled slider, preserved drag positions.

**Phase 3 — B6 on the chassis.** Waterfall (zoom + click in definition of done), matrix (log visualMap day one), scatter (2D selection lasso). With the chassis each is a thin builder inheriting correct behavior; without it each triples the surface area of exactly the pain documented above.

**Acknowledge and park (explicitly, so they're decisions not omissions):** accessibility is currently zero (no aria/roles/keyboard anywhere — mouse-only drill model); no `@media` queries (untested at split-pane widths); long-running-tab memory is unmeasured, and note that moving to instance reuse makes a leaked chart live forever — add a soak check to chaos when P5 lands; the CLI (`src/output.c`) is a second presentation layer whose %DB/idle/truncation semantics should be audited against the web's once the web's are pinned; a UTC/local toggle is cheap and worth a line in FUTURE_WORK; `saveAsImage` export is nearly free once the toolbox exists. Comparison mode is the one real new capability — design it after URL state.

**What NOT to do:** migrate libraries or trial-run a replacement outside the build/mount seam; slim or custom-build the vendored bundle; hand-roll a DFG renderer; add a SPA framework or router beyond hash state; virtualize tables preemptively (cap + "N more" first); pursue appendData/streaming (irrelevant to 5s poll-and-replace); build multi-value filter algebra now (chips over the existing FilterStack cover the 80% case); batch-fix visual defects before the gallery exists (you'll have no before/after and no regression net).

## Non-issues — don't chase these ghosts

Things that look like problems but verify as fine (or much smaller than they look):

1. **"Old data stretches to the 'now' edge / AAS crops to data extent."** Refuted. Both server paths emit dense zero-filled buckets spanning exactly the requested `[from,to]` (`compute.c:375-381, 1469-1474`; `server.c:1748-1783`); a quiet tail renders as zeros at the right edge. The only real residue is the axis ending one bucket-width before `to` — which is precisely what breaks the escalation markLine (P2), so fix it there.
2. **"Category axes hide time gaps."** Refuted twice. Heatmap and concurrency both emit full uniform grids (`server.c:2787-2799`; `compute.c:1292, 2171`); gaps render as empty columns at correct positions. What survives is a consistency note (mixed axis regimes, no shared cursor), not a truthfulness defect.
3. **"Charts re-animate from zero every 5s in live mode."** Mostly refuted: the main live AAS chart already reuses its instance with `animation:false`; the timeline custom series has no entry animation (real artifact = teardown flash + tooltip loss); concurrency/transitions are off the live loop by default. The genuine animation replay is on user gestures and the DFG slider (P5).
4. **"A mid-refresh legend rebuild leaves the chart stuck soloed."** Inverted: the trailing `apply(sel)` (`active.js:240`) *cancels* an in-progress hover-solo — the chart pops back to all series under your cursor. Still a bug, opposite direction.
5. **"Charts are universally inert."** Overstated: the AAS chart has drag-select zoom and dblclick zoom-out — a hand-rolled brush that a grep for ECharts interaction APIs misses. The dimensional-drill absence (P3) stands.
6. **"fmtPct(null) blanks the Overview today."** Latent, not live: the server currently always emits numeric pct on the unguarded paths (`server.c:1829, 2137`); null pct exists only where the client already guards. Guard anyway (P1) — it is one server change from firing.
7. **"A bug can't become a deterministic repro."** Overstated: pgwt-server is a trace-replay server; copying the trace dir (`demos/capture-trace.sh`) + `tests/server_harness.py` reproduces exact payloads. The recorder (Section 6, item 9) is convenience, not capability.
8. **Bundle size / version.** The vendored build is 5.5.1 (zrender 5.6.0 embedded caused the confusion), 1.03MB, go:embed'd, cached locally — a non-issue; do not spend effort on it. One nit for the next upgrade: migrate `timeline.js:32`'s deprecated v4 `styleEmphasis` and rebaseline per the vendor README.

**The one-paragraph summary:** keep the composition, keep ECharts, keep the builder/test architecture — they are genuinely good and rare. Spend days making failure visible and the mock browsable, a week or two building the gallery and fixing chart identity, then wire the seven drill links and URL state. After that, "looks weird" becomes a named checklist violation with a gallery cell, drill-down becomes the full ASH loop, and the B6 views land on a chassis instead of copy-pasting today's defects.
