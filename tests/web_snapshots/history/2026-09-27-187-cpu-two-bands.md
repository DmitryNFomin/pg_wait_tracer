# 2026-09-27 — #187: surface the off-CPU AAS series as two CPU bands

Seven baselines REGENERATED and one gallery baseline ADDED:
table_overview.png, aas_chart_overview.png, fidelity_sampled_shading.png,
gallery/aas-dense.png, gallery/aas-sampled.png,
gallery/aas-mixed-escalation.png, gallery/aas-escalated-live-edge.png,

Cause: `web/static/lib/builders/aas.js` stacked only the classes in
`WAIT_CLASSES` (`lib/format.js`), which had no `offcpu` entry, so the
per-bucket `offcpu` series the server already computes and sends was
silently dropped from every AAS chart. Fixing that (adding an `offcpu`
entry, rendered adjacent to `cpu` via the new `AAS_CLASS_ORDER`, plus
renaming `cpu`'s legend label to "CPU (running)") changes any snapshot
whose payload carries a nonzero `offcpu` value or that renders the AAS
legend/Time-Model-table at all:

- `aas_chart_overview` (11.04% px) / `fidelity_sampled_shading` (11.03% px):
  `tests/mock_server.py`'s AAS buckets already carried a small nonzero
  `offcpu` value (deliberately, per its own T8 comment) that no chart ever
  painted before this fix — these two now show the previously-invisible
  band, which is the bug (#187) being fixed, confirmed visually.
- `table_overview` (1280x373 -> 1280x402, +29px): the Time Model table
  gained the "CPU (waiting for a core)" row (mock_server.py's `time_model`
  now includes it, conserving `CPU (running) + CPU (waiting) + Σwaits ==
  DB Time` at 12760ms instead of silently excluding the row's 260ms).
- `gallery/aas-dense`, `gallery/aas-sampled` (derived from dense),
  `gallery/aas-mixed-escalation` (derived from dense),
  `gallery/aas-escalated-live-edge` (uses the dense dataset directly): all
  four are small (~0.3%) reflow diffs from the AAS legend gaining a 12th
  chip ("CPU (waiting for a core)", always rendered even at value 0 in
  these fixtures) and 'cpu' growing from "CPU" to "CPU (running)" — no
  data values in these four fixtures changed.
- `gallery/aas-cpu-running-waiting` (new cell): added to
  `GALLERY_STATIC_CELLS`/`web/static/dev/fixtures/aas.mjs` specifically to
  pin the split visually per the issue's request — buckets 0-29 show a
  real cpu/offcpu split (~35% waiting for a core), buckets 30-59 mimic a
  mid-window tier switch to the combined-only value, at the identical
  group total (no visible step).
