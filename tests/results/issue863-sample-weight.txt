src/sampler.c:538-547: only the elapsed<nominal floor was removed.
First tick: retain nominal p as the defined edge term. Between first and last
ticks, weights telescope exactly. In the server's [first,last] query the first
sample's backward edge is clipped away; including [first-p,first] adds exactly
p once. This is an edge estimate, not a measurement of capture startup latency.
Non-monotonic now<=last: retain nominal defensive fallback, avoiding underflow.
Late: measured interval, including 5p, up to the existing 60s cap. This is a
bounded estimator of the state observed at the end, not evidence it held during
the gap. Beyond 60s: the excess is unobserved/uncredited time, attributed to no
state and not carried to the next tick (last_tick is updated at sampler.c:997).
No new counter: the retained-cap option was chosen. Timer lateness remains
unbounded in sampler_tick_late_ns_total; it is not an isolated excess-gap metric.
Existing timer counters remain exported at control.c:325-328, unchanged.
Restart: sampler_start allocates fresh zeroed state (sampler.c:777-779); the
first tick gets only p, never the old daemon's gap. Tested at the pure helper.
Escalation: sampler never stops (escalation.c:1-7). Server exact-wins subtraction
(server.c:4185 onward) removes exact coverage from backward sample intervals.
The first post-END tick is tested: 90ms interval, 50ms inside exact coverage,
40ms sampled tail; a surrounding 100ms window is 60ms exact + 40ms sampled.

Weight path / downstream audit
------------------------------
sampler.c:988 takes the timestamp before target reads; :994 obtains the weight;
:1487 feeds live accumulation; :1500 passes it to pgwt_writer_push_samples.
The writer stores it as the SAMPLES block's sample_period_ns. Nearby-period
batching formerly used an integer weighted mean, losing nanoseconds and moving
weight between ticks/backend populations. event_writer.c:1310-1315 now flushes
on ANY period difference; equal-period pushes still batch. Jittered captures
will usually write a block per tick. No format change.
event_reader.c:247 reads the header; server.c:1647-1649 and :2436-2438 normalize
each sample to old_event + duration_ns=header weight. server.c:4185 subtracts
exact coverage and clips the query. compute.c:1497 uses the clipped duration
for DB Time; compute.c:958 splits backward intervals over AAS buckets.
The inspected paths do not require weight>=nominal. The existing first-tick,
clock-fallback and stall-cap rules are preserved.
