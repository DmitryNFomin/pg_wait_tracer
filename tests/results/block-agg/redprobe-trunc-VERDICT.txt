WHAT WAS ASKED
--------------
"Prove the assertion still goes RED when the property it guards is broken.
If it cannot fail, it is decoration."

The assertion:
  tr.check_eq(canonical_body(after), canonical_body(ctl),
              "the truncated read matches a fresh uncached read exactly")
  -- tests/test_data_current_trace_cache.py:1036, after repointing :1029
     from "transitions" to PROBE_CMD (session_timeline).

The property it is supposed to guard, per cur_cache_sync's own comment
(src/server.c:1185): "A cache that cannot prove what it holds must refuse to
answer, never answer anyway."

THREE FINDINGS
--------------
F1. THE EQUALITY ASSERTION IS VACUOUS IN THIS SCENARIO. Note `served: 0`: the
    retained superset is never served. Truncating current.trace to a third of
    its size makes the coverage layer refuse the file on BOTH servers, so both
    answer empty ({"events": [], "fidelity": "none", "total_count": 0}) and
    agree trivially. The assertion compares empty to empty. It is satisfied
    without checking anything -- "the thing being checked is absent rather
    than wrong".

    This is NOT an argument for the adviser's alternative. With "transitions"
    on both sides it was equally vacuous: both sides refused identically. The
    repoint makes the assertion COHERENT (same command, so it can hold at all);
    it does not make this scenario able to exercise the property.

F2. "the entry did not keep blocks the file no longer has" PASSED at (2 -> 2)
    while the entry kept both blocks the file no longer has. Its predicate is
    `post["blocks"] <= pre["blocks"]`, which is satisfied by keeping all of
    them -- it can only catch GROWTH, never retention, so it cannot fail in the
    direction its own text describes. PRE-EXISTING: untouched by this branch
    (not in any hunk of `git diff 8705412..HEAD -- <this file>`).

F3. Only `resets` bites. It went red under M1 alone and under M1+M2, so the
    section is not blind -- but the specific property "must not serve the stale
    superset" is unprovable in this fixture, by either command.

WHAT WOULD BITE (follow-up, not done here)
------------------------------------------
A truncation that leaves the file READABLE, so the coverage layer still accepts
it and the cached server can actually serve blocks the file no longer has --
e.g. lowering only the .meta committed count, or truncating to an exact block
boundary. Then cached-vs-uncached would genuinely diverge and the equality
would have something to see. That needs a new fixture shape; it is a task, not
a nit, and it is NOT folded into this branch.
