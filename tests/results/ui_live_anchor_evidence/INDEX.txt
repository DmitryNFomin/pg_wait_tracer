ui_live_anchor_evidence -- why tick 1's blink-sweep anchor was moved
====================================================================

Every number in ui_live_smoke_lib.py's FRAME_SPACING_DRIFT_BOUND_MS comment,
in ui_live_smoke.py's tick_baseline comment, and in the commit message that
removed tick 1's frame-1-2 exemption, is derived here. Regenerate all of it:

    sh scripts/regen.sh          # run from this directory

That reads corpus/ and rewrites tables/. If a table changes, something drifted.

corpus/<run.id>/summary.json
    31 ui_live runs, 2026-09-27 .. 2026-10-07, REDUCED to the only four fields
    the analysis reads (target_offsets_ms, achieved_offsets_ms, capture_ms per
    tick; ttfp_ms per tab). Full summaries for these runs are 3.3 MB; reduced,
    488 KB. scripts/reduce_corpus.py built them and documents the reduction;
    verify.py, anticorr.py and headroom.py were diffed against the unreduced
    originals and produce byte-identical output.

    corpus/<run.id>/origin.txt names the artifact each run came from. Eight are
    in-repo (tests/results/ui_live_gate1_healthy_run{1,2,3_postfix,4_bound150},
    ui_live_gate{1,2}_bypass, ui_live_gate2_healthy_run{1,2}) and can be
    re-reduced to check this corpus. The rest came from sibling agent
    worktrees, which get deleted when their PRs land -- that is why these are
    committed rather than cited by path.

    CHRONOLOGY COMES FROM run.id (unix epoch seconds written by the run), never
    file mtime: every committed artifact shares one checkout mtime, which would
    silently collapse the whole time series into a single instant.
